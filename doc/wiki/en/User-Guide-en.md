# User Guide

Administrators of legacy installations using the default password must change it in the setup wizard first. The wizard can read setup status; restricted APIs return JSON errors instead of web redirects. Background tasks stay hidden during setup and until the password is changed.

## Create a notebook

When creating a notebook, choose its school stage (primary, junior high or senior high) and subject. They decide which knowledge-point library the AI uses and cannot be changed later, so keep separate notebooks per stage and subject.

Primary school offers math, English and Chinese. The built-in Chinese library includes chapters and knowledge points for grades 1–6, junior high and senior high. After upgrading Docker or an installation package, startup fills in missing built-in Chinese tags while preserving existing tag IDs, question links, custom tags and other tag systems.

After an administrator imports the PEP curriculum knowledge points (see [Settings and Users](Settings-and-Users-en)), a **Tag system** option appears when creating a notebook. It coexists with the built-in system and cannot be changed after creation; AI recognition and knowledge-point filters only use tags from the notebook's tag system.

The notebook list shows only each name and question count; click one to open its detail page, where you can rename or delete it. Only an empty notebook can be deleted, so move or delete its questions first.

## Add questions

| Entry | When to use |
| --- | --- |
| Image upload, drag and drop, camera | Paper tests, workbooks and existing question images |
| Clipboard paste | Copied screenshots or images, with `Ctrl/⌘+V` |
| Screenshot | The browser supports screen sharing and the page runs in a secure context |
| AI solve | You already have the question text; Markdown and LaTeX are supported |
| Direct entry | Manually record a known question, answer and analysis |

Images can be cropped first. While cropping or selecting several questions, zoom with the mouse wheel, a two-finger pinch or the buttons at the top right (100%–500%; click the percentage to reset). When one image contains several questions, select them all for a batch import. Keep the full question, any required figure and the student's work, and avoid blurry images or cut-off conditions.

When selecting multiple images, the crop dialog shows the current image number and processes them in selection order. Rotate and crop each image, click "Confirm and next", then "Finish cropping and import" on the last image. In the default single-question mode, all images form one question, such as a passage and questions on separate pages. They are recognized together in one request and saved as one question with every source image. Only explicitly selecting multi-question mode imports each region as a separate question. The mode stays fixed after confirming the first image; cancel and select again to change it. Canceling discards unsubmitted crops. Review, source-image viewing and backups preserve image order.

Multi-image requests do not send the first image twice or reduce image resolution further. Limits are 20 images, 20 MiB of encoded transfer data per image and 50 MiB combined. The server proxy accepts up to 80 MiB to accommodate older clients that duplicate the first image and the question text.

After enabling "Review before import" in "Settings → General", you can correct the recognition on the review page before saving. The AI may misread numbers, symbols and figure relationships, so check against the original before saving.

## Student answers and administrator review

Students share the administrators' question bank and exams while keeping independent review progress and submission results. AI grading saves per-question results and mistake analysis after each submission.

Opening Review follows the student's schedule and loads only questions currently due, with a blank answer form; it does not carry over the previous review's answers, handwriting or AI grading. Correct answers schedule the next review after 1, 3, 7 and 14 days in sequence, while a wrong answer can be redone the same day. When no questions are due, the latest review detail is shown. The current page shows the answers and grading from the submission just made. Exam pages can still restore the latest submission for that exam. My answer shows submitted text, selected options or handwritten images, while grading notes, mistake analysis, reference answers and explanations support Markdown and formulas. Reference answers and explanations are returned only after that question has been graded; administrators can inspect previous results in Student submissions.

Open Admin dashboard → User list → View details → Student submissions. Switch between Review records and Exam records to see submission times, grading status, correct counts and accuracy. View grading opens paginated question snapshots, figures, student text or selected answers, handwritten images, reference answers, explanations and AI feedback. Click a handwritten image to enlarge it.

Accuracy includes only successfully graded answers; pending or failed answers are excluded. Refresh reads the latest stored status. Viewing records does not call AI or require resubmission. Saved question and answer snapshots remain available after source questions are edited or deleted. Only administrators can access this view.

## Duplicate detection

On import, the question text is compared with the current user's existing questions across all notebooks. The default threshold is 90% and can be changed in your general settings.

- When the similarity is **strictly greater** than the threshold, the existing question is returned and a wrong attempt is recorded on it.
- A similarity equal to the threshold does not count as exceeding it.
- Similarity is the character edit similarity of the normalized question text; it does not mean the math is the same.
- Records from repeated imports feed into later mastery evaluation; check the original question's answer history when needed.

Notebooks also offer a two-question similarity comparison to help decide whether the threshold suits your questions. If only a few characters of numbers or conditions differ, the similarity may still be high, so judge by the meaning of the question.

## Question details

Each question shows its text, answer, analysis, knowledge points, difficulty, semester and paper level, plus the original photo.

| Information or action | Notes |
| --- | --- |
| 6-character question ID | Copy it and locate the question by ID in a notebook; shown as the source ID in printouts |
| 1–5 star difficulty | Rated by the AI with reference to competition-math difficulty; can be changed manually |
| Grade/semester | Click **Edit grade/semester** to change and save it; review also offers a selector, and loading the profile preserves manual edits |
| Paper level | When not set, 1–3 stars default to the "Paper A" group and 4–5 stars to the "Paper B" group; a manual choice takes priority. Customize groups in **Settings → General → Paper Groups**: rename defaults, add custom groups (e.g. Unit Test, Midterm, Final), deactivate or delete custom groups |
| Knowledge points | Tags from the matching stage and subject; re-recognize one question or a whole notebook |
| Regenerate full solution | Generates a new answer and analysis; asks for confirmation before overwriting |
| Fix LaTeX | Appears when formula syntax issues are detected, letting the AI correct the formulas |
| Original image | View, replace or add it to check the recognition |

Unrated questions are not assigned a paper level by the default rule alone. Regenerating the full solution keeps the knowledge points and mistake information.

## Figures and animated explanations

- **Question angle labels**: basic geometry compares explicit Chinese or English degree statements against labels with the same visible vertex and two rays. AOB and BOA name the same angle; a different vertex cannot borrow its label. Repeated labels must agree, and a right-angle square represents 90 degrees. Integers, decimals and fractions with °, 度 or degree(s) are compared exactly while retaining their wording. Unknowns, angle identifiers, approximate values, compound expressions, questions, assumptions, proofs and candidate statements remain conservative. Drawing coordinates do not supply ordinary angle measurements or answers. Clearly scoped panels are checked independently, with complete legacy figures, original images or manual figures available on conflict. Legacy SVG still needs mathematical checking.
- **Structured text readability**: new structured SVG output checks a minimum template font size of 12px, including dense table cells. Dense number lines first try readable label sizes; number-line and coordinate axes preserve decimal values and reachable endpoints. Long division reserves room for the remainder label. Titles, units or labels that cannot fit trigger a fallback to compatible legacy SVG, or no new figure when none is usable, without truncating text or shrinking it further. Existing figures remain unchanged. Actual displayed text size still depends on scale and zoom, and recognition results need checking against the original image.
- **Cube nets**: the fixed template is used only after six equal squares pass a local foldability check. Disconnected, duplicated, non-foldable or uncertain layouts keep the legacy figure, original image or manual figure instead of being treated as cuboid or composite-solid nets.
- **Fraction diagram consistency**: fraction bars and circles are generated only when numerator, denominator, partition count and filled count are explicit, non-negative integers that agree exactly. Unknowns, expressions, decimals and negative values remain available as ordinary stacked fraction text, but cannot drive guessed shading metadata. Mixed fractions keep their whole units; when the diagram contract is not certain, the application keeps the legacy SVG, original image or manual figure instead.
- **Question-to-fraction checks**: when a question uniquely states “the fraction is 3/4” or “the numerator is 3 and the denominator is 4,” including the corresponding Chinese wording, structured numerator and denominator text are compared item by item. Candidate comparisons, questions, assumptions, quotations, multiple fractions and complex expressions remain conservative skips; explicit conflicts trigger whole-figure or whole-group fallback without rewriting text or making another AI request.
- **Integer digit-count conditions**: explicit integer digit counts use the absolute value of known numbers, excluding signs and leading zeros; both `034` and `34.0` are checked as 34. `3.4` is not a two-digit integer, and even a tiny nonzero fractional part is not rounded away. Figure text retains its original wording. Unknown digit boxes keep their existing place-count checks; complex expressions are not evaluated and answers are not filled in. Decimal arithmetic without an explicit digit-count condition keeps its existing rules. This does not provide general decimal-point alignment.
- **Explicit measurement checks**: new structured figures check equal square sides, cube edges, opposite horizontal sides of rectangles and parallelograms, radii and diameters of one circle, and explicit degree labels on right-angle marks. A chord cannot exceed a known diameter or twice a known radius in the same circle. Length labels for the same endpoint pair must agree even when the endpoints are reversed or the segment is listed as both a chord and a diameter; different chords do not have to be equal. Integers, decimals, ordinary fractions and limited mixed numbers support exact internal comparison with common metric units, while saved labels retain their wording. Unitless values are compared only with other unitless values. Unknown formulas and angle identifiers are not evaluated. Drawing dimensions and illustrative chord angles do not determine physical lengths, and missing units are not inferred. Contradictions trigger whole-figure or whole-group fallback; legacy SVG is sanitized only for safety, so check the question and original image. If AI Redraw Figure returns no usable output, the existing figure is kept and the background task reports failure with retry available.
- **Question-to-arithmetic cross-checks**: one complete integer or decimal expression, or an explicit condition such as “a two-digit number times 25”, checks values, signs, operator and both stated digit counts. Common LaTeX operators and English operation words are supported. Valid, explicitly labeled and fully separated leading dates (such as “Date: 2026-11-15.”), time ranges and question ranges are not treated as expressions. Only consecutive headers at the start are excluded; body text, formulas, invalid dates and unseparated content remain conservative. Common parameter-free styles (such as `\displaystyle`) and spacing commands do not cancel value checks, rewrite text or hide calculation structure in commands with arguments. Exact decimal comparison leaves saved text unchanged: `3.4×25` is not reduced to `4×25`, and a fraction slash is not treated as division. Compound, chained, unknown or multiple candidate expressions are not reduced to fragments. Conflicts try the complete legacy SVG; no new figure is returned when no usable output exists. Original images and manual figures remain available. This does not provide general formula evaluation or decimal-point alignment.
- **Named main-figure statements**: statements such as “Triangle ABC is an isosceles triangle” and “ABCD is a square,” including common Chinese forms, check triangle subtypes and common quadrilaterals. Basic polygons match case-sensitive visible point names and boundary order; hidden IDs and interior points cannot replace a vertex. Cyclic and reversed boundary order are accepted, while crossed order or an explicitly missing point triggers whole-figure fallback. The current parser supports three or four single-letter Latin point names only; area, solid and coordinate templates cannot express these vertex names and do not stand in for named polygons. Composite diagrams, uncertain contexts and candidate statements in choice or judgment questions remain conservative; original images and legacy figures remain available.
- **Question-to-main-figure checks**: limited direct statements such as “The figure is a square” or “下图是一个正方形” check area figures, solids and an unambiguous single basic polygon. Equal-sided rectangles and equal-edged cuboids remain valid. Basic polygons retain rotation, reversed vertex order, collinear intermediate points and internal construction lines. Only explicit complete equal-side labels are compared, without treating partial sides or diagonals as full sides, calculating physical lengths from coordinates, or moving original points. Trapezoids require exactly one parallel pair. Calculation questions retain the shape constraint. Shape questions, truth judgments, proofs, assumptions, quotations, partial diagrams, multiple shapes, circles, separate exterior elements and figure groups do not establish one main polygon. Clear conflicts trigger whole-figure fallback; still check against the original image.
- **Closed-segment main figures**: without `polygons`, a basic figure participates in question-shape checks only when all solid segments form exactly one simple closed cycle. Open chains, multiple cycles and extra solid segments remain conservative skips; dashed internal construction lines may remain, and validation never changes the segments.
- **Visible point names**: basic, number-line, coordinate and circle figures require unique visible names made from a Latin letter with optional digits, subscripts and prime marks, including the center. Duplicates after full-width ASCII and whitespace normalization cause whole-figure fallback. Case, subscripts versus digits and different prime forms stay distinct; descriptions, hidden IDs and other notation are not inferred as names. Points are never renamed, merged or moved, and separate panels may reuse names.
- **Number-line point labels**: all markers, including unnamed points, participate in collision and association checks. Labels avoid the axis, ticks and other text; different names at the same value are retained and placed together. Tick and title anchors stay fixed, and the canvas trims whitespace around the complete drawing without moving points, removing ticks or changing values. Unreliable layouts trigger whole-figure or whole-group fallback. Saved figures use the layout after regeneration; wide figures can still scroll within the reading region.
- **Question relations**: when the question explicitly says connect `AB`, segment `AB`, `∠ABC`, `AB∥CD` or `AB⊥CD`, the program checks the named points, segments, angle rays and parallel/perpendicular directions in the same subfigure. Polygon boundaries count as sides; ambiguous notation remains conservative and falls back to the original image, legacy figure or manual figure.
- **Question coordinates**: coordinate templates compare visible matching point names, x/y order, signs and complete finite decimals against explicit statements such as “Point A has coordinates (1,2)” and common Chinese forms, without floating-point tolerance. Unmatched names in a single figure are not guessed. Clearly scoped panels are checked independently; missing names or conflicts cause whole-group fallback. Transformations, other coordinate systems, relative coordinates, vectors, polar coordinates, questions, assumptions, proofs, candidate statements and unknown expressions remain conservative skips. Points are not moved, values are not supplied, and basic geometry's relative layout is not mathematical coordinates. Original images, legacy figures and manual figures remain available, without extra AI requests.
- **Missing point names in question relations**: if some normalized point names in a relation are present in the figure while others are missing, the whole figure falls back instead of silently dropping the relation. If all names are absent or the notation cannot be uniquely parsed, the rule stays conservative to avoid treating variables or ordinary text as geometry. Common wording such as “connect point A and point B” is supported; validation never invents points, moves points or adds segments.
- **Option-scoped figure-group checks**: when the question separates panels with wording such as “Figure A: …; Figure B: …”, “Option A: …; Option B: …” or “(A) …; (B) …”, the program checks each panel's point, segment, angle, circle, main-shape and arithmetic conditions only within its matching clause; an explicit conflict or missing named relation falls back for the whole group. Latin labels shaped like point names (`A`, `A1`, `A₁`, `A′`) require punctuation, parentheses or an explicit figure/option prefix; whitespace alone is not enough, avoiding ambiguity. Unscoped comparisons and “which option is correct?” questions remain conservative, and candidate statements in multiple-choice or true/false questions are not treated as figure facts.
- **Circle question relations**: explicit `radius OA`, `chord AB`, `diameter AB`, `connect AB`, `central angle AOB`, `inscribed angle ACB`, `arc AB`, `major arc AB`, `minor arc AB`, `semicircle AC`, `sector AOB` and the corresponding Chinese or English wording are checked against the circle center, circumference points, `radii`, `chords`, `diameters`, `arcs` and `sectors`. A diameter may satisfy a chord reference, but an ordinary chord cannot satisfy a diameter reference; a radius and both sides of a central angle must connect the center to circumference points, a matching sector may express the central angle, and an inscribed angle requires two actual chords. Two-point arcs use `arcType`; the middle point in a three-point arc name must lie inside the selected arc, whose side may be selected by `through` or `arcType`, without requiring the JSON to repeat the question label. A semicircle requires diameter endpoints plus a third point. Postfix wording such as “AB is a chord” and “AB is a diameter” is supported. Ambiguous notation remains conservative and falls back without inventing segments.
- **Arc and sector circle scope**: dedicated circle diagrams also check the specified center for arcs, major/minor arcs, semicircles and sectors. Scope continues across commas, switches at a new explicit circle reference and ends at a sentence, semicolon or line break. An arc name must contain two or three distinct circumference points; the center cannot serve as the third point. Following English length or area descriptions are kept separate from point names, preserving digits, subscripts and primes. Direction checks use only the structure's own `arcType` and `through`; omitting both keeps the actual minor arc rather than borrowing a third point from the question to change direction. A clear center or point conflict causes the whole figure to fall back. Ambiguous longer names remain conservative rather than being truncated into another arc. Basic geometry still does not infer arc directions or sector regions.
- **Circle relations in composite geometry**: `basic_geometry` checks explicitly named radii, chords, diameters, central angles and inscribed angles. Circumference points must lie on the corresponding circle, named segments must actually be drawn (polygon edges count), and diameters must pass through their center. Wording such as `圆O中`, `在圆O内`, or `in circle O` scopes validation to that circle. An inner/outer circle reference must match one existing `circles.label` in full; names are never inferred from radius size, and duplicate names cause fallback. A full circle name takes priority over a center-point match. Scope continues across comma-separated relations, changes at a new explicit circle reference, and ends at a sentence, semicolon or line break. Merely mentioning several circles does not establish ownership. Concentric circles named only by their shared center remain candidates according to their radii. Arc directions and sector regions require `circle_geometry` or fallback to the legacy figure or source image; lines are never inferred from point positions.
- **Triangle subtypes**: explicit main-figure statements of isosceles, equilateral, right and isosceles right triangles check area templates and a single basic triangle. Equal complete sides need consistent labels. Right triangles with three explicit complete side values in matching unit categories are checked exactly against the Pythagorean relation. Unknown expressions, partial sides, internal heights and vertex descriptions do not provide side lengths or answers; missing units are not inferred. Area templates accept `apexRatio` from -1 to 2; values 0 and 1 allow the right-angle vertex at either end of the base, where the height is a complete side. Limited coordinate tolerance does not relax exact numeric-label checks.
- **Heights outside the base**: triangle, parallelogram and trapezoid templates can draw a height meeting a base extension, including its dashed perpendicular, dashed base extension and right-angle marker. The extension is excluded from the base-length label, unknown lengths remain unchanged, and no answers are calculated. Automatic quadrilateral heights start at an outer upper vertex; named feet or specified vertices require basic geometry. Complete diagrams fit proportionally, with whole-figure fallback and original/manual images available for dense cases. Saved figures use the new layout after regeneration.
- **Triangle side relationships**: an explicit main-triangle statement checks that any two of three known complete side lengths in matching unit categories have a sum strictly greater than the third. Both 3cm, 4cm, 8cm and 3cm, 4cm, 7cm trigger fallback. Internal unit conversion is exact and leaves labels unchanged. Unitless values do not borrow units; unknown sides, partial segments and internal heights cannot stand in for complete sides. Questions, judgment tasks, assumptions and candidate statements remain conservative. Conflicts retain the legacy SVG, original image or manual figure for checking, without changing values or filling answers.
- **Rhombus figures**: an explicit main-rhombus statement checks four equal sides, parallel opposite pairs and visible boundary order; squares also qualify. Complete side labels must agree, excluding partial segments, diagonals and perpendicular heights. Simple base-height figures can reuse area templates. Relative drawing dimensions do not determine physical lengths, and stated side lengths and heights are checked against their own existing labels. Questions, assumptions, proofs and candidate statements are not imposed as facts. Explicit conflicts cause whole-figure or whole-group fallback to the legacy SVG, original image or manual figure without changing coordinates or filling answers.
- **Arithmetic blanks**: newly generated structured arithmetic keeps boxes, question marks, underscores and unknown digits without solving the blanks from known operands. Multiplication rows retain their labels and digit shifts. Division steps require explicit digit shifts and can keep quotient or remainder blanks. Duplicate positions or shifts beyond a known integer operand cause the whole figure to fall back. Existing integer values can still be recomputed, which does not prove correct transcription. Saved figures are unchanged; legacy SVG fallback is not validated for mathematical correctness.
- **Reading arithmetic**: newly generated arithmetic uses a compact canvas based on its content. Integers and simple unknown digits use fixed columns, keeping boxes and digits aligned despite different glyph widths. Unambiguous decimal addition and subtraction without partial products align decimal points. Decimal multiplication aligns the last digit and places decimal points between columns, preserving trailing zeros and unknown boxes without recalculating decimal values or filling answers. Partial-product shifts cannot exceed the digit count of a multiplier with explicit numeric or unknown-digit positions, excluding signs and the decimal point. Division uses a dedicated long-division bracket with the quotient above, divisor on the left, dividend inside and aligned subtraction rows; an optional remainder appears below the steps. Notes follow the complete calculation, with at most three lines and fonts of at least 12px. Content that cannot fit causes the whole figure to fall back without clipping the note or placing it among the rows. Long calculations can still scroll. Decimal division, complex expressions and unclear column relationships remain complete text rows; general formula typesetting is not provided. Saved figures use the new layout after regeneration.
- **SVG figures**: common figures are recognized as structured data and rendered as static SVG by local templates for details, practice and printouts; the original image can still be viewed separately. Figures include a **View larger figure** control; on phones, use the buttons, wheel or two-finger pinch in the viewer to inspect dense tables and geometry labels. SVGs with explicit, reliably measurable font sizes open at a reading size of at least 12px at 100%. Wide and tall figures scroll inside the viewer; focus the reading region for arrow-key or page-key navigation. This size is independent of the page's saved figure scale. Use Fit whole figure / Reading size to inspect the overview or restore readable labels. Each mode uses its own initial size as 100%, and switching modes resets zoom. Manual images and unmeasurable legacy SVGs continue to fit the full image. Zoom uses positions within the image so centering whitespace and padding do not push narrow figures to one side. Buttons zoom around the visible image center, within scroll boundaries. The cropper uses the same rule and keeps crop regions relative to the original image. Closing the viewer does not change the saved figure scale.
- **Geometry on phones**: newly generated structured basic geometry, circle and coordinate figures reduce outer whitespace using complete shape and text bounds, preserving stroke clearance, question coordinates and equal axis scale. This makes labels larger at the same available width. Saved figures keep their existing canvas until regenerated. Dense labels, long titles and very long axes may still need **View larger figure**; saved scale and alignment settings continue to apply.
- **Arcs and sectors**: circle templates support major arcs, minor arcs and semicircle sides. A semicircle uses a third point on the circle to identify its side. Small radial coordinate errors are aligned to the radius while preserving direction, using the same projection for validation and drawing. Distinct point IDs that coincide after alignment, zero-length chords, or diameter endpoints outside the existing center tolerance cause whole-figure fallback. Point names are not merged, segments are not removed, and endpoints are not moved to repair a conflict. Nearby points in different directions are not treated as coincident using the arc-direction threshold; label placement is checked separately. Conflicting relationships, ambiguous sides or points outside tolerance fall back to compatible legacy SVG; keep the original image for checking or use a manual figure when neither is usable.
- **Grid labels**: square cells, row and column counts, and shaded positions are preserved. Cells and the canvas expand as needed, with up to three text lines per cell and a minimum font size of 12. If complete labels still cannot fit, the figure falls back without dropping text or moving it to other cells. Use **View larger figure** to inspect dense grids.
- **Mathematical labels**: characters such as `cm²`, `m³`, `A₁` and `½` are preserved; normalization only folds full-width ASCII and tidies whitespace. Grids, tables and charts keep common numeric values, contiguous expressions and common units intact when wrapping. Width estimates use Unicode grapheme clusters, so combining accents, variation selectors and joiners are not counted twice. Paired `$…$`, `$$…$$`, `\(…\)`, `\[…\]` formulas and a finite set of common raw commands with complete arguments, including `\frac {1} {2}`, `\sqrt [3] {27}`, `\mathbb {R}`, `\operatorname {lcm}`, `\substack {a=1\\b=2}`, `\overset {?} {=}` and paired `\left … \right`, stay indivisible, and SVG text does not run through KaTeX. Incomplete or unrepresentable content falls back conservatively without splitting the number or dropping text. Complex formulas and composite figures still need checking.
- **Chart ranges and labels**: bar charts keep a zero baseline, and value labels avoid bars, category text, titles, units and axes together; line charts use the actual data and explicit `minValue` / `maxValue` instead of expanding small decimal data to `1` or turning an all-negative range positive. Line-chart value labels also avoid segments and points. If labels cannot be preserved and placed readably, the complete legacy figure, original image, or manual figure is used.
- **Geometry label placement**: basic geometry, circle diagrams and coordinate planes place point names, segment lengths, angles, sectors, arc labels and circle names together to avoid segments, circles, angle marks, point markers, fixed text and other labels. Labels for segments, radii, diameters and chords use the full text box to choose a position beside the middle portion of the segment, with checks against association with neighboring segments. Radius labels also have a movement limit based on radius length. The entire angle label stays inside its angle, outside the marker and within the usable ray lengths. Sector text stays inside its original sector, and arc text outside the corresponding arc. Labels in major sectors cannot cross into the excluded minor sector. The full circle-name box stays inside its own circle; names of intersecting circles avoid overlap regions, and an outer concentric circle uses the annulus, preventing ambiguous associations. Titles, coordinate ticks and free descriptions retain their original anchors; a collision with geometry or text, or an out-of-bounds label, causes a fallback. Light gray coordinate grids are treated as background; axes and question lines participate in collision checks. Placement never moves geometry or removes labels. If no reliable space is available or an angle marker is too small, it falls back to compatible legacy SVG; check the original or use a manual figure when needed. Complex figures and recognition results still need checking.
- **Figure display scale and alignment**: saved mistakes with a figure show this setting on the details page. Enter a percentage or drag the slider to preview, from 10–200% (default 100%), and choose an alignment (left / center / right, default center); exam papers with figures also allow adjusting scale and alignment per question or uniformly across the exam. Click **Save** to apply it after reload and in printouts. **Reset to 100%** restores the default scale; save again to keep it. SVG and manual figures scale once; the container limits wide figures without shrinking narrow figures twice. Enlarged figures fit the available width and keep their aspect ratio. Backups retain the scale and alignment; existing questions and older backups default to 100% and center. **Image Scale** in print preview controls the original photo; enable **Question Text** to print the figure.
- **SVG animated explanations**: the animation stays paused on the first frame when opened or changed; click Play to start. Step-by-step demonstrations of the solution with pause, seeking, replay and full screen; enabled by default in personal settings. Finite decimals, ordinary and mixed fractions, and common metric units are converted only during validation, while original text is preserved; unitless numbers are compared only with other unitless numbers, without supplying missing units. Formula fragments, operator suffixes, unknown expressions, area units, questions, assumptions and proof goals do not establish a known length; no physical length is inferred from coordinates and missing labels are not filled. Explicit conflicts cause whole-figure or whole-group fallback.

- **Main-figure dimensions and orientation**: explicit dimensions following a clear main-figure statement are checked against corresponding numeric labels in area and solid templates. Chinese and English prefixes and 2–4 item lists such as `length and width are 6 cm and 4 cm respectively` or `length, width, and height are 4 cm, 3 cm and 2 cm respectively` are supported. Dimension names and values must map one-to-one in order; a unit stated only on the last value is shared only by that explicit list syntax, and other missing units are not inferred. Rectangles and cuboids may swap horizontal length/width assignments together when orientation is unspecified; height and trapezoid upper/lower bases retain their roles, and triangle vertex descriptions are not side lengths. Depth requires an explicit depth label, without assuming a horizontal or vertical direction. Dimensions from other objects or auxiliary lines, area/solid category mismatches, questions, assumptions and unknown formulas are handled conservatively. No values are supplied and no physical length is inferred from coordinates. Explicit conflicts cause whole-figure or whole-group fallback; original images and manual figures remain available.

- **Cylinders and cones**: AI figure regeneration, similar questions and new exam questions can use `round_solid` for right circular cylinders and cones. Cone outlines are tangent to the projected elliptical base. Separate dimension lines identify radius, diameter and axial height; slant height labels the sloping edge. Known values check the radius/diameter and cone Pythagorean relations and dimensions following a clear main-figure statement. Original units, fractions and unknowns are retained without filling answers. Extreme proportions, labels that cannot fit or explicit conflicts cause complete fallback. Oblique solids, frustums, nets and composite solids are outside this template. Upload recognition still does not redraw figures; original images and manual figures remain available, with no additional model requests. Check recognition against the original even when the template is valid.
- **Spheres**: `sphere_geometry` represents complete spheres only. The fixed template draws a circular outline, a solid front and dashed back equator, and separate radius/diameter dimension lines. Long English labels, mixed fractions and units are placed below the dimension line while retaining their source text and association. Explicit radius and diameter values must satisfy the two-times relation; unknowns remain unchanged. Hemispheres, shells, sections, cutouts, composite solids and cross-figure size comparison stay outside the template. Semantic conflicts or labels that cannot fit cause whole-figure or whole-group fallback, while original images, manual figures and legacy SVG remain available.
